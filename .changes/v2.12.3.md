[2.12.3](https://github.com/gina-io/swig/tree/v2.12.3) / 2026-11-15
-------------------------------------------------------------------

* **Fixed** Native swig's `{% autoescape %}` tag fails at compile when it has no argument, with "Expected true, false, "html" or "js" in autoescape tag on line N.", where it turned escaping off; a string other than "html" or "js", in either quote style, fails with the tag's "Unexpected token" error, where the built-in `e` filter gave HTML escaping and a replaced `e` filter received the string; so a custom strategy that a replaced `e` filter handles, such as "css", now fails in the tag, while the `autoescape` option still passes any string to the `e` filter. Both refusals happen at compile, also in a part of a template that never renders (the top level of an extending template outside its blocks, a block the parent template does not define, the top level of an imported file), where such a template rendered on both render paths. The end of a nested region now restores the enclosing region instead of the template default: with autoescape off, `{% autoescape true %}{% autoescape false %}{{ v }}{% endautoescape %}{{ v }}{% endautoescape %}` renders `<i>&lt;i&gt;` for v = "<i>", where it rendered `<i><i>`.

* **Fixed** In native swig a per-call `autoescape` option set to undefined reads as true, as swig-twig and swig-jinja2 read it: `render("{{ v }}", { locals: { v: "<i>" }, autoescape: undefined })` renders `&lt;i&gt;`, where it rendered `<i>`, whatever the instance's own default. The same value in the instance options reads as true too: an instance made with `new swig.Swig({ autoescape: undefined })`, and the default instance after `swig.setDefaults({ autoescape: undefined })`, escape `{{ v }}`, where they rendered `<i>`.

* **Fixed** Native swig keeps text that is not a whole comment as text, as swig-twig, swig-jinja2 and swig-django do. Text that ends with the comment close rendered nothing: `a #}`, `#}` and `{# c #}#}` rendered an empty string, and `x {# c #} y #}` rendered `x `. An unclosed comment open such as `{# unclosed` rendered nothing too, and so did text that ends with a custom comment close (`x -->` with `cmtControls: ['<!--', '-->']`). An error raised after such text named a line too low, since the line breaks of that text were not counted. A whitespace control before such text now applies to that text, as in swig-twig: `{{ v -}} x #}{# c #} y` renders `Vx #} y` for v = "V", where it rendered `Vy` (the text was dropped and the control stripped the next text).

* **Fixed** Native swig refuses, as Jinja2 and Django do, a second `{% else %}`, or an `{% elseif %}` or `{% elif %}` after the else branch, in one `{% if %}`, with "Multiple "else" branches in "if" tag on line N."; such a template compiled to invalid JavaScript and failed with a raw "Unexpected token 'else'". The refusal happens at compile, so it also fails a template that holds such a tag in a part that never renders: the top level of an extending template outside its blocks, a block the parent template does not define, or the top level of an imported file. There the sync render path rendered the template; the async render path rendered it in the first case and failed with the raw error in the other two.

* **Fixed** A native `{% for %}` loops over a numeric subscript such as `{% for x in arr[0] %}` or `{% for x in m[0][1] %}`, which failed to compile with "Unexpected number "0" on line N." while a string subscript such as `obj["k"]` already worked.

* **Fixed** Native `groupBy` leaves out a null or undefined item of the list, as it leaves out an item that does not hold the key, where `{{ items|groupBy("k") }}` over a list such as `[null, {"k": "a"}]` failed with the TypeError "Cannot convert undefined or null to object".

* **Fixed** Templates compiled by 2.12.2 or earlier keep their old output for the native autoescape and comment fixes until they are recompiled with 2.12.3: the compiler decides the end of a nested `{% autoescape %}` region, a tag with no argument or with another string, an `autoescape` option set to undefined, and text that ends with the comment close or starts with an unclosed comment open. So such a body still restores the template default at the end of a nested region, still turns escaping off for a tag with no argument or an undefined option, and still drops that text. The `groupBy` fix is in the runtime and reaches them at once; a template with a second else, or with a numeric subscript in a for loop, did not compile on 2.12.2. Recompile precompiled templates (swig compile output, registerBundle bundles, stored precompile() results) with 2.12.3.
