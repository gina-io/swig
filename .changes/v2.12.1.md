[2.12.1](https://github.com/gina-io/swig/tree/v2.12.1) / 2026-11-03
-------------------------------------------------------------------

* **Security** A key from the template data that names the prototype chain (`__proto__`, `constructor` or `prototype`) now reads as missing wherever a template reads a value with it: in a subscript such as `{{ foo[k] }}`, in a call on one such as `{{ foo[k](x) }}`, in the bracket fragments a tag registered with setTag receives, and in the attribute argument of swig-jinja2's groupby and sum. The key is compared as JavaScript converts it to a property name, so a list holding one of the names counts too. Before, such a key reached the object's prototype and the Object and Function constructors: `{{ foo[k] }}` printed the Object constructor, a call on such a value could run text from the data as JavaScript, and a value read this way could be written through a dotted `{% set %}` (native, Twig, Jinja2), an include given it with `with … only` (native, Twig) or Twig's `{% with … only %}`, which put a property on Object.prototype for the whole process. A template is exposed when it indexes a value with a key that the request controls. Every release has it, native back to the original swig 1.4.2 and each flavor since its first release, and the async render path has it as well. An empty member bracket, such as `foo[]` in a custom tag's fragments or in a malformed native output, now fails with « Unexpected closing square bracket on line N. » instead of a raw SyntaxError.

* **Security** Native `{% set %}` no longer writes through the prototype chain when a key from the data inside its target's brackets names it: `{% set obj[k].x = "v" %}` and `{% set obj[k][j] = "v" %}` with k = `"__proto__"` (or a list holding it) put a property on Object.prototype for the whole process, and `{% set obj[k] = value %}` replaced obj's own prototype. Such a key now throws « Unsafe assignment to "__proto__" via bracket notation is not allowed (prototype-chain guard) on line N. » when the template runs, the message a quoted name already gets when the template compiles. A prototype-chain name written as a variable inside the brackets, such as `{% set obj[constructor] = "v" %}`, now fails at compile time, as a read of that name does; before, it read the context's inherited member and wrote under its text. swig-twig and swig-jinja2 refuse bracket targets in a set, and swig-django has no set tag. Every native release has it, back to the original swig 1.4.2.

* **Security** Templates compiled by an earlier release keep their old behaviour until they are recompiled with 2.12.1. The checks for a native set target and for a custom tag's bracket fragments are in the code the compiler emits, so `swig compile` output, registerBundle bundles and stored precompile() results built by 2.12.0 or earlier still write and read through the prototype chain when 2.12.1 runs them. A subscript compiled by 2.9.10 or later calls a runtime helper and is guarded once 2.12.1 runs it; one compiled before 2.9.10 is not. Recompile precompiled templates with 2.12.1.
