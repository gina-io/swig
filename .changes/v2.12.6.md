[2.12.6](https://github.com/gina-io/swig/tree/v2.12.6) / 2026-11-21
-------------------------------------------------------------------

* **Fixed** A template function compiled with `codegenMode: 'async'` and registered with `register()`, `registerBundle()` or `run(tpl, locals, path)` no longer prints `[object Promise]` when a sync render reaches it, in all four flavors and the runtime-only build. A sync `{% include %}` of it, or a call a helper makes to `compileFile` or `renderFile` for it while a sync render runs, now fails with an error that names the template and says to render the page on the async render path or to register a sync-compiled function (swig-django renders an empty string for such a helper, as it does for any callable that raises). A top-level call such as `compileFile(path)(locals)` still returns the Promise, and an include marked `ignore missing` renders an empty string. Precompiled templates need no recompile.

* **Fixed** On the async render path, the check that decides whether a for loop, a tag that wraps its content in a function of its own (such as with or filter) or a macro awaits now blanks the string literals of the compiled code in one pass, in all four flavors: it used a regular expression that took time quadratic in a line's length on an unclosed quote followed by many escaped quotes of the same kind, which the code of a tag registered with `setTag` can hold (a comment holding 60,000 of them took about 10 to 15 seconds to compile on 2.12.5 in one measurement, and takes about 3 ms now). The check gives the same answers as before: the new blanking returns what the regular expression returned on every string of up to 7 characters made of the two quotes, a backslash, a line feed, a carriage return and a letter, and on 200,000 random strings.
