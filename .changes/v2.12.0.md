[2.12.0](https://github.com/gina-io/swig/tree/v2.12.0) / 2026-11-02
-------------------------------------------------------------------

* **Added** swig-jinja2: Jinja2's filters `string`, `items`, `attr`, `filesizeformat` and `forceescape`, which 2.11.0 rejected as unknown filters. `string` gives the text of a value, `items` the key and value pairs of a mapping (`{% for k, v in d|items %}`), `attr` an attribute of a value (`user|attr("name")`), `filesizeformat` a number of bytes as a human-readable size, reading its input as Python's `float()` does (`1234567|filesizeformat` is `1.2 MB`, `"1_000"|filesizeformat` is `1.0 kB` and `1536|filesizeformat(true)` is `1.5 KiB`), and `forceescape` escapes a value even when it is already escaped (`"&amp;"|forceescape` is `&amp;amp;`). Where they differ from Jinja2: `string` and `forceescape` give an empty string for None, and the JavaScript text of a boolean, list or mapping (`true|string` is `true` and `[1, 2]|string` is `1,2`, where Jinja2 writes `True` and `[1, 2]`); `forceescape` writes a double quote as `&quot;` where Jinja2 writes `&#34;`, the same text on screen; `attr` reads a name as `value.name` does, so it also reads a key of a mapping and a JavaScript property such as the `length` of a string, where Jinja2 reads attributes only, and it gives an empty value for `__proto__`, `constructor` and `prototype`, which `value.name` rejects when the template compiles. Where Jinja2 raises an error, these filters give a value: `items` an empty list for a value that is not a mapping, `attr` an empty value for an undefined value or a name that is not a string, and `filesizeformat` its input unchanged (`"abc"|filesizeformat` is `abc`).

* **Added** swig-jinja2: Jinja2's `urlize` filter, which 2.11.0 rejected as an unknown filter. It turns the URLs and email addresses in a text into links by Jinja2 3.1.6's rules: `http://`, `https://` and `www.` links, bare domains under com, net, int, edu, gov, org, info and mil, IPv4 and IPv6 hosts, and `mailto:` and plain email addresses; a leading `(` and a trailing `.`, `,` or `)` stay outside the link unless a `)` closes a `(` inside it (`(http://example.com).` keeps `(` and `).` outside, `http://example.com/foo_(bar)` keeps its `)`). It escapes the rest of the text, gives every link but an email link `rel="noopener"`, and its output is not escaped again. Its arguments are positional, in the order `urlize(trim_url_limit, nofollow, target, rel, extra_schemes)`: write `none` to leave one unset (`u|urlize(none, true)` adds `nofollow`); a keyword argument such as `target="_blank"` fails to compile. Where it differs from Jinja2: None gives an empty string; a double quote is written `&quot;` where Jinja2 writes `&#34;`, the same text on screen; and swig-jinja2 has no Markup type, so `urlize` escapes again a value that `escape`, `safe` or `forceescape` has already been through (`x|safe|urlize` escapes the HTML in x, which Jinja2 keeps as it is), and an `escape` after `urlize` escapes its links. A limit that is not an integer (`urlize("10")`) leaves the links uncut, and an extra scheme that is not a scheme prefix is ignored, where Jinja2 raises an error.

* **Fixed** swig-django: `pluralize` reads a string count as Django does, with Python's `float()`. A decimal digit of any script reads as its value (a count of U+0661, the Arabic-Indic one, gives the singular suffix, where 2.11.0 gave the empty string); U+0085 before or after the number is whitespace (2.11.0 gave the empty string), and U+FEFF is not (a count with a U+FEFF before or after the number gives the empty string, where 2.11.0 read the number). On an engine without Unicode property escapes, decimal digits outside ASCII are still not read.
