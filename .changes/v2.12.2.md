[2.12.2](https://github.com/gina-io/swig/tree/v2.12.2) / 2026-11-08
-------------------------------------------------------------------

* **Fixed** A key from the data that an object gets only from Object.prototype reads as missing in a subscript, in a call on a subscript and in the swig-jinja2 attribute reader of groupby, sum and attr: with foo {}, `{{ foo[k] }}` printed the source of the function for k = __defineGetter__ (native) or __lookupGetter__ (swig-jinja2), and now renders as a key foo does not hold. A key written in brackets in the template reads the same way: `{{ foo["hasOwnProperty"]("b") }}` printed true and now renders nothing, while the dotted form `{{ foo.hasOwnProperty("b") }}` reads as before. Own keys, the members of a class and the methods that String, Number and Array define still read; a method a string gets only from Object.prototype now reads as missing (`{{ s[k]() }}` with s "abc" printed abc for k = toLocaleString and now renders nothing), and a Proxy whose get trap answers every key now gives nothing for such a name, as a plain object does. For these names the check looks at the first 1000 objects of a prototype chain: a name that only an object further down holds reads as missing here and in native `in`, where it read before (a chain of 1001 objects whose last one holds toString). A native set target still writes such a key as an own key, and the bracket fragments a custom tag receives read the four Object.prototype accessor helpers (__defineGetter__, __defineSetter__, __lookupGetter__, __lookupSetter__) as missing, even when the object holds one as its own key.

* **Fixed** A key in the data, a template name or a block name that is also the name of an Object.prototype member is read as an own key. A for loop over a mapping that holds a key named hasOwnProperty, or over an object with no prototype, no longer fails with « obj.hasOwnProperty is not a function » in any flavor, and neither does a macro call, or an include with an object, when the context holds such a key or has no prototype; a native block named hasOwnProperty works through extends and {% parent %}. A for loop no longer asks a mapping's own hasOwnProperty function which keys to visit: over a mapping {a, _b, hasOwnProperty} whose hasOwnProperty function leaves out _b, every flavor rendered [a][hasOwnProperty] and now renders [a][_b][hasOwnProperty]. The memory loader no longer serves an inherited member as template source: an include of __proto__, constructor or another Object.prototype name such as toString fails as a missing template does, where native failed with « source.replace is not a function » and swig-twig, swig-jinja2 and swig-django rendered [object Object] for __proto__ and the source of the function for the others. Native groupBy groups the values constructor and __proto__, and a value that converts to one of them such as the list ["__proto__"], where it failed with « out[keyname].push is not a function », and swig-jinja2 groupby groups the values hasOwnProperty and __proto__, where it failed or split the __proto__ group in two. A key "__proto__" in the data stays an own key where a filter maps over an object, where swig-twig merge copies one, where a swig-jinja2 loop filter keeps a mapping item, and in the copies that an include with an object and swig-twig {% with %} make; before, it set the new object's prototype, so the key was lost and the fields of its value read as the object's own. With the memory cache, a template that a custom loader names __proto__ is loaded once, not on every render.

* **Fixed** Native `in`, a key test, no longer finds the members every object gets from Object.prototype: with obj {b: 1}, `{% if k in obj %}` was true for k = constructor, toString, __proto__ or hasOwnProperty, and is now false. Own keys, keys inherited from another prototype (the methods of a class) and array indexes still count, and a string on the right still throws.

* **Fixed** Names every object gets from Object.prototype no longer reach a template through an import, a block name or an object literal. On the async render path, swig-twig and swig-jinja2 `{% from "m.html" import toString as t %}` bound the toString function of Object.prototype (`[{{ t }}]` printed its source) and now binds nothing, as a name the template does not export; the same for valueOf and hasOwnProperty, while an exported macro named hasOwnProperty, which failed with « obj.hasOwnProperty is not a function », now binds. A native block named __proto__ fails to compile with « Unsafe block name "__proto__" is not allowed (prototype-chain guard) », where a child's override of it was lost (the parent's content rendered); blocks named constructor, prototype or toString still work. In an output or a built-in tag of native, swig-twig and swig-jinja2, an object literal key "__proto__" is now an own key: `{% set o = {"__proto__": {"a": "P"}, "b": 1} %}` made {"a": "P"} the prototype of o, so `{{ o.a }}` printed P and the json filters left the key out; now `{{ o.a }}` renders nothing and the key is kept, as Jinja2 reads it, and a literal that holds the key twice, which failed to compile with « Duplicate __proto__ fields are not allowed in object literals », keeps the last value. The fragments a custom tag receives are unchanged.

* **Fixed** Templates compiled by 2.12.1 or earlier keep their old answer for native `in` and for an object literal key "__proto__" until they are recompiled with 2.12.2: those checks are in the code the compiler emits, as is the new code of a swig-jinja2 loop filter and of an async {% from %}. A subscript, or a call on one, compiled by 2.9.10 or later calls a runtime helper and follows the 2.12.2 rule at once. A template compiled by 2.12.2 needs the 2.12.2 runtime: run by 2.12.1, native `in` throws « _utils.hasKey is not a function » and a swig-jinja2 loop filter « _utils.setOwn is not a function ». Recompile precompiled templates (swig compile output, registerBundle bundles, stored precompile() results) with 2.12.2.
